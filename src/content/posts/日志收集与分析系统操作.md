记录「日志收集与分析系统操作」实验的完整过程：在 Kali Linux 中用 Docker Compose 部署 Loki + Promtail + Grafana，实现本地 journald 日志的实时采集、集中存储与可视化展示，再通过 Grafana Explore 与自定义 LogQL 查询、Dashboard 面板完成日志级别分布统计与错误/警告趋势监控。

## 实验目的与原理

**实验目的**：部署 Loki 日志系统，实现本地日志集中化（实时采集、存储查询、可视化展示）。

**实验原理**：在 Kali Linux 中部署 Loki + Grafana，用以收集和查看本地虚拟机系统的日志记录。经过实验 2 的操作，学生应该能够初步熟悉如何部署 Loki + Grafana，并为后续实验 3、4 的靶机日志收集与查看、基于 AI 算法的日志检测与分析等实验做好准备。

## 实验软硬件环境

- Kali Linux 虚拟机（以 VirtualBox 为例）
- Docker 与 Docker Compose（用于拉取并编排 grafana/loki:2.9.4、grafana/grafana:10.3.1、grafana/promtail:2.9.4 三个容器镜像）

### 步骤3：创建 docker-compose.yml

注意：因为 Kali Linux 中 rsyslog 默认没开启，所以这里使用的配置为添加 Kali Linux 中使用的日志工具 journald 的日志目录挂载，如果要使用在一般的 Linux，以下命令需要作出相应修改。

使用以下命令，创建 docker-compose.yml：

```yaml
cat > docker-compose.yml <<'EOF'
version: '3.8'

services:
  loki:
    image: grafana/loki:2.9.4
    container_name: loki
    ports:
      - "3100:3100"
    volumes:
      - ./loki-config.yml:/etc/loki/local-config.yaml
      - loki-data:/loki
    command: -config.file=/etc/loki/local-config.yaml
    restart: unless-stopped
    networks:
      - loki-network
    healthcheck:
      test: ["CMD-SHELL", "wget --no-verbose --tries=1 --spider http://localhost:3100/ready || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 5

  grafana:
    image: grafana/grafana:10.3.1
    container_name: grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin123
      - GF_USERS_ALLOW_SIGN_UP=false
    volumes:
      - grafana-data:/var/lib/grafana
      - ./grafana-provisioning:/etc/grafana/provisioning
    restart: unless-stopped
    networks:
      - loki-network
    depends_on:
      loki:
        condition: service_healthy

  promtail:
    image: grafana/promtail:2.9.4
    container_name: promtail
    volumes:
      - /var/log/journal:/var/log/journal:ro
      - /run/log/journal:/run/log/journal:ro
      - /etc/machine-id:/etc/machine-id:ro
      - ./promtail-config.yml:/etc/promtail/config.yml
    command: -config.file=/etc/promtail/config.yml
    restart: unless-stopped
    networks:
      - loki-network
    depends_on:
      - loki

networks:
  loki-network:
    driver: bridge

volumes:
  grafana-data:
  loki-data:
EOF
```

![通过 heredoc 写入 docker-compose.yml 编排文件](./images/LogAuditExp2/log-05.png)

### 步骤4：创建 Loki 配置文件

```yaml
cat > loki-config.yml <<'EOF'
auth_enabled: false

server:
  http_listen_port: 3100
  grpc_listen_port: 9095

common:
  path_prefix: /loki
  storage:
    filesystem:
      chunks_directory: /loki/chunks
      rules_directory: /loki/rules
  replication_factor: 1
  ring:
    kvstore:
      store: inmemory

ingester:
  lifecycler:
    ring:
      kvstore:
        store: inmemory
      replication_factor: 1
  chunk_idle_period: 5m
  chunk_retain_period: 30s
  wal:
    dir: /loki/wal

schema_config:
  configs:
    - from: 2020-10-24
      store: boltdb-shipper
      object_store: filesystem
      schema: v11
      index:
        prefix: index_
        period: 24h

storage_config:
  boltdb_shipper:
    active_index_directory: /loki/boltdb-shipper-active
    cache_location: /loki/boltdb-shipper-cache
    cache_ttl: 24h
    shared_store: filesystem
  filesystem:
    directory: /loki/chunks

compactor:
  working_directory: /loki/boltdb-shipper-compactor
  shared_store: filesystem

limits_config:
  reject_old_samples: true
  reject_old_samples_max_age: 168h
  ingestion_rate_mb: 16
  ingestion_burst_size_mb: 32

chunk_store_config:
  max_look_back_period: 0s

table_manager:
  retention_deletes_enabled: false
  retention_period: 0s
EOF
```

### 步骤5：创建 Promtail 配置文件

注意：因为 Kali Linux 中 rsyslog 默认没开启，所以这里使用的配置为添加 Kali Linux 中使用的日志工具 journald 的日志目录挂载，如果要使用在一般的 Linux，以下命令需要作出相应修改。

使用以下命令，创建 promtail 配置文件：

```yaml
cat > promtail-config.yml <<'EOF'
server:
  http_listen_port: 9080
  grpc_listen_port: 0

positions:
  filename: /tmp/positions.yaml

clients:
  - url: http://loki:3100/loki/api/v1/push

scrape_configs:
  - job_name: journal
    journal:
      max_age: 12h
      labels:
        job: systemd-journal
        host: kali-linux
    relabel_configs:
      - source_labels: ['__journal__systemd_unit']
        target_label: 'unit'
      - source_labels: ['__journal__hostname']
        target_label: 'hostname'
      - source_labels: ['__journal__transport']
        target_label: 'transport'
      - source_labels: ['__journal_priority_keyword']
        target_label: 'level'
EOF
```

![创建 promtail-config.yml，配置 journald 日志采集与标签重写](./images/LogAuditExp2/log-07.png)

### 步骤6：创建 Grafana 数据源自动配置

```yaml
cat > grafana-provisioning/datasources/loki.yml <<'EOF'
apiVersion: 1

datasources:
  - name: Loki
    type: loki
    access: proxy
    url: http://loki:3100
    isDefault: true
    editable: false
    jsonData:
      maxLines: 1000
      derivedFields:
        - name: "IP Address"
          matcherRegex: "from\\s+(\\d+\\.\\d+\\.\\d+\\.\\d+)"
          url: "$${__value.raw}"
EOF
```

## 测试/调试及实验结果分析

启动服务时，在 exp2 目录下执行 `docker-compose up -d`，通过 `docker-compose ps` 查看容器状态，loki、grafana、promtail 均为 Up 状态；查看 promtail 日志，输出 “starting journal target” 和 “receiving journal entries”，表明日志采集功能正常。验证环节，`curl http://localhost:3100/ready` 返回 “ready”，说明 Loki 服务就绪；`curl -I http://localhost:3000/login` 返回 HTTP/1.1 200 OK，确认 Grafana 可访问。通过 logger 命令生成测试日志 “TEST_MESSAGE_FOR_LOKI_JOURNALD_xxx”，`journalctl -n 10 --no-pager | grep TEST_MESSAGE` 能查到该日志，等待 5 秒后用 curl 查询 Loki 接口，结合 jq 工具成功返回测试日志内容，验证了日志从采集到存储的全流程正常。

任务 2 创建 Grafana 面板时，首先在 Explore 界面用 `{job="systemd-journal"}` 查询所有 journal 日志，再用按级别、单元等过滤的 LogQL 语句测试，均能返回正确结果。创建“日志级别分布”Stat 面板时，输入三个 LogQL 查询（分别对应错误、警告、信息级别），设置 Legend 为中文，可视化类型为 Stat、水平排列、经典配色，面板正确显示了各级别的日志数量。创建“错误与警告趋势”Time series 面板时，使用 rate 函数计算 10 分钟内的错误和警告日志速率，设置 Line width 为 2、Fill opacity 为 20、Point size 为 5，Legend 显示在底部并展示 Last 和 Mean 值，面板正常展示了趋势曲线。

调试过程中曾遇到 curl 查询 Loki 时提示 “Command 'jq' not found”，通过 `sudo apt install jq` 安装后解决问题；初始拉取 Docker 镜像速度较慢，通过配置国内镜像加速器后拉取速度显著提升。

本次实验成功通过 Docker Compose 部署了 Loki + Promtail + Grafana 日志系统，实现了 Kali Linux 本地 journald 日志的实时采集、集中存储和可视化展示。Promtail 正确挂载了 Kali 的 journal 日志目录，将日志推送到 Loki 存储；Grafana 自动配置了 Loki 数据源，通过自定义 LogQL 查询和面板配置，实现了日志级别分布统计和错误/警告趋势的可视化，达到了实验目标。

### 总体思路总结

- 组件分工：Promtail 负责采集（挂载 `/var/log/journal`、`/run/log/journal` 与 `/etc/machine-id`），Loki 负责存储与索引（boltdb-shipper + filesystem），Grafana 负责查询与可视化，三者通过 `loki-network` 桥接网络互联。
- 配置自动化：Grafana 数据源通过 `grafana-provisioning/datasources/loki.yml` 自动注入，容器启动后无需手动添加数据源即可直接用 Loki 查询。
- 查询入口：Explore 界面是验证 LogQL 的主入口，标签（job/unit/level/hostname）+ 管道过滤（`|=`）组合即可快速定位某一服务或某一类级别的日志。
- 可视化要点：Stat 面板适合表达“各级别日志数量”这类聚合值，Time series + rate 适合表达“错误/警告随时间变化的趋势”，Legend 命名与单位决定面板可读性。
- 注意点：`version` 字段在较新版本的 docker-compose 中已废弃（会有 WARN 提示）；实验结束必须 `docker-compose stop`，否则容器继续占用 3000/3100 端口影响后续实验。
